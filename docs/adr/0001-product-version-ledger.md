# ADR 0001：使用独立产品版本台账记录发布演进

- 状态：已接受
- 日期：2026-10-10

## 背景

仓库原有 `README.md` 的当前版本、前端/后端包版本、API 版本和业务数据版本含义不同，且没有专门的产品发布历史。系统页面需要展示当前产品状态，合并前也需要有可检查的版本记录。

## 决策

采用根目录 `CHANGELOG.md` 作为产品发布版本的唯一历史台账；`README.md` 只保留当前产品版本并链接台账；“系统信息”页面展示当前产品版本和各版本层级，同时链接台账。

合并到远端 `main` 或提交指向 `main` 的 PR 前，必须更新台账。纯文档、测试或依赖维护不改变产品行为时，保留“无产品版本变化”的说明，不递增产品版本。

## 结果

- 产品发布版本与技术包、API、业务数据版本不会混淆。
- 版本历史可通过 Git 审查，与功能代码在同一提交中保存。
- 页面和文档仍需同步更新当前产品版本，因此 PR 模板提供检查项降低遗漏概率。
