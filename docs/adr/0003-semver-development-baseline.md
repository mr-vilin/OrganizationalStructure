# ADR 0003：采用 SemVer 并重设开发基线

- 状态：已接受
- 日期：2026-10-24
- 依据：用户确认采用 SemVer，且尚未正式上线，明确要求从 0.1.0 开始。
- 替代范围：ADR 0001 中每个产品变更 PR 都递增、手工同步页面及当前旧编号的约定。

## 决策

以 docs/versioning.md 为唯一版本规范，以根目录 version.json 为产品版本声明。旧 v1.0、v2.8.62、v2.8.63 及当时证据原样归档为历史开发记录，不视作正式发行序列，也不追造缺失的版本历史。

0.1.0 是开发初始基线，不因无预发布后缀就宣称生产上线。0.x 的破坏性变化与新功能均递增 minor，修复递增 patch；形成稳定公开契约后再明确进入 1.0.0。版本规范、产品版本、包版本、API 契约、数据库结构和业务数据版本分开管理。

版本声明随代码受 Git 管理，构建元信息随镜像保存。数据库不作为软件版本来源，不新增版本表或执行迁移。CHANGELOG 使用 Unreleased 收集开发改动，以版本而非日期作为记录单位；tag/Release 与实际部署分别管理。

## 验收与限制

提供版本格式、发布记录、历史不可变、递进及 tag 一致性校验；CI 接入校验、相关测试与构建。系统信息页显示本次前端构建和受保护的后端运行元信息。兼容性等级依赖人工评审，真实部署、数据库与飞书环境需要独立验收；文档或构建通过不能代替上线事实。
