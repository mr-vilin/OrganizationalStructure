# ADR 0004：初始化重来及流程切换时清理业务数据，保留访问与审计

- 状态：已确认并在本地实施，隔离 MySQL 和浏览器关键流程验证通过；尚未部署。
- 日期：2026-10-26（北京时间）。
- 依据：[首次初始化向导需求澄清](../architecture/initialization-wizard-clarification-2026-10-26.md) Q1、Q2、Q6 的用户答复，以及 Q11 后对 Q8 的修订。

尚未初始化成功时，后台初始化任务中断即视为该次尝试失败，下一次从头执行。用户已确认，重来时清空此前初始化留下的部门、人员、关系、门店资料（含编码、备注）与临时采集结果，保留飞书配置、管理员白名单、登录能力、失败原因和操作审计。浏览器关闭、刷新或短暂断网而后台任务仍运行，不构成初始化任务中断。

该边界要求旧业务残留不参与下一次初始化，同时保留管理员重新进入系统和排查失败的依据。仅保留暂存清理不足以消除历史业务残留；连配置、管理员资格和审计一并清空则会丢失重新进入系统与定位失败的基础。此项清理会移除门店本地资料；日常同步不执行这类清理。

Q6 补充确认：失败后保留错误原因，不自动重启同步。管理员手动点击“重新开始”时执行上述清理，再从第一步重跑全部预检；全部通过后仍由管理员点击“立即同步”。

用户随后修订 Q8：“没有历史包袱，旧项目可以重新按这个流程重新同步一次”。本次流程切换因此不保留旧实例的初始化豁免；无论旧完成标记为何，均先使其失效，再由管理员在向导内发起按同一边界清理，重新执行新流程一次。原先“旧已完成实例保留状态和业务数据”的决定已被替代。切换后成功完成的新状态保持有效，不因普通启动或发布反复重置，也不扩大为永久性的日常整库重置入口。

实现将旧任务终结、旧事件隔离，保留任务摘要、错误及必要审计，使其失去后续执行或恢复旧业务数据的资格。清理采用单事务与一致锁序，任务世代及数据集世代隔离旧执行；重来不废除仍健康的空闲 worker 租约。完成标记、业务发布与任务成功同事务提交。具体方式见需求澄清文档的实施基线及[迁移说明](../architecture/initialization-wizard-migration-2026-10-26.md)。本地验证不代表业务数据库清理或部署已经执行。
