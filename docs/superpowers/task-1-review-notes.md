# Task 1 接续检查点

供正式审查核对最终代码，以下是阅读实施中版本发现的风险，不预先判定最终结果。

- 批量只改变门店标记时，缺省编码/备注是否保留已有资料，尤其取消标记后的历史资料。
- 门店资料验证的 fields 错误是否在 HTTPException handler 中保留，前端能否定位编码冲突。
- API 客户端轮换是否在同一事务内完成旧凭据失效与新凭据生成，失败后会不会把旧凭据单独撤销。
- 所有写入是否有身份、CSRF 和合理的请求字段约束；日志能否记录白名单/API 凭据管理操作但不泄露秘密。
- 初始化前管理 status 与任务查询能否解释状态，公共读接口 503 语义是否保持。
- MySQL 取回 UTC naive 时间后，HTTP 响应是否补上 UTC 时区标记，避免浏览器将其当成本地时间解析。
- 初始 Alembic revision 是否导入实时 Base.metadata；后续改模型时，旧迁移必须保持冻结，不能悄悄创建未来表结构后又重复执行增量迁移。
