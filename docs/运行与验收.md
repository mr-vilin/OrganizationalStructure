## 能力与观察层验收（2026-10-15）

### 范围与契约

公开 Python 入口为 `app.capabilities`，导出 `OrganizationCapabilities`、`AgentContext`、`CapabilityResult`、`Observation` 及稳定错误。适配器继续调用现有业务服务；飞书仍是部门、员工和关系的权威来源，本地只写门店标记、编码与备注。公共/管理 API 的 `data/meta` 和错误 envelope 保持原契约；本轮不提供 MCP 工具、真实 Agent 或企业飞书验收。

内部 HTTP 返回 `operation_id/data/observation/audit`。普通业务读取和预览不新增回执，`operation_id` 为 null；回执查询返回已有 operation_id。读取本地快照成功的 `submitted` 只表明本次查询完成，`fact_quality` 仍按覆盖、对象质量和投影状态区分 `resolved/partial/unknown/inconsistent`。找不到或已取消的门店不会被当作“正常空门店”；查看观察结果的 `target_status` 和 `next_action`。`verified` 不能由请求被接受推断。

写操作回执持久化 `recorded/accepted/submitted/failed`，观察执行维度另有 `request_recorded/accepted/running/submitted/verified/partial/failed/unconfirmed`；事实质量和执行结果分别判断。原 `SyncJob` 继续使用 `queued/running/succeeded/failed`。同步返回 `accepted` 后应查询任务与回执，成功但有未解析事实可表现为 `partial`，不能把 HTTP 202 当成业务提交完成。

门店提交必须同时传 `expected_epoch`、`expected_version` 和幂等键；预览后数据变化返回 `409 DATASET_CHANGED`。事实、本地资料、门店投影、变更日志、操作回执和版本在同一事务提交或回滚。相同主体、环境、幂等键与规范化请求重放同一 `operation_id`；同键不同内容返回 `OPERATION_CONFLICT`。长调用者 ID 完整保存在 `requested_by` 和回执中，任务的有界 `trigger_source` 使用 `human_agent/ci_agent`；复用或重试保留原触发来源。

响应丢失时，通过 `GET /internal/capabilities/operations/lookup?idempotency_key=...` 查询；也可按 `/operations/{operation_id}` 查询。Python `get_operation` 要求 operation_id、idempotency_key 二选一，且只查询当前主体/环境自己的回执。历史回执保留原提交世代和版本，证据另列当前版本；数据集世代变化后观察为 `unconfirmed/inconsistent`，不能伪装为当前提交。分页继续绑定世代、版本及筛选条件，冲突后整组重读。

### 内部服务鉴权

`/internal/capabilities` 要求独立的 `ORG_AGENT_SERVICE_TOKEN`，通过 `Authorization: Bearer ...` 传递；留空拒绝所有调用。可信身份头是 `X-Agent-Actor-Type`、`X-Agent-Actor-Id`、`X-Agent-Environment`、可选 run/case ID 和批准布尔值；环境必须等于 `ORG_AGENT_ENVIRONMENT`。production 写入要求受信服务声明真实人工批准 `X-Agent-Approved: true`。普通 API 密钥、Cookie/CSRF、伪造/重复身份头、环境不匹配均不获得该权限。CI 还要求隔离 `test` / 实际 `_test` 数据库和测试 run_id。反向代理与 sidecar 私网边界见[部署说明](../deploy/README.md#内部能力服务与-sidecar-边界)。

### 数据库前后检查与恢复

本轮仅对新建 `organization_agent_test` 操作，服务为官方便携 MySQL **8.4.11**，仅监听 `127.0.0.1:13306`。Docker daemon 仍不可用；本轮的真实通过来自便携进程。执行前实际查询确认库名后缀、MySQL 8.4、`REPEATABLE-READ`、数据库 `utf8mb4/utf8mb4_0900_as_cs`、迁移已到 `0006_column_comments`、回执表不存在、现有外键类型/字符集/排序规则不兼容数为 0。

0007 仅创建 `operation_receipt`，不转换任何已有表、字段或已有唯一键；新表无外键，现存数据不存在新唯一键冲突或外键孤儿迁移问题。保留 SOURCE_ID 的 `utf8mb4_bin` 比较规则，新表默认显式 `utf8mb4_0900_as_cs`，不修改全局 TABLE_ARGS 或旧表的比较语义。ORM 与 0007 同步包含 InnoDB、字符集、排序规则以及 19 个字段的非空中文 COMMENT。

实际执行 `alembic upgrade head`，0006 → **0007_operation_receipt** 返回 0；未使用 stamp 或 create_all。执行后实际 `SHOW CREATE TABLE` / `INFORMATION_SCHEMA` 证实新表 InnoDB、utf8mb4、utf8mb4_0900_as_cs、19 列中文注释、原唯一键与索引以及 ID 列 utf8mb4_bin。新连接、双连接、连接池复用和失效重连均实际核对 `character_set_client/connection/results=utf8mb4`、`collation_connection=utf8mb4_0900_as_cs`。仅传 PyMySQL collation 参数曾被 SQLAlchemy 的 SET NAMES 覆盖；连接工厂现于方言初始化之后恢复明确会话配置。

迁移失败先停止后续测试并保存脱敏错误，查询 alembic_version、SHOW CREATE 与实际列/索引；MySQL DDL 不保证事务回滚。不得直接 stamp 跳过、在未知结构上反复补表或转换旧表。只有确认目标仍是可丢弃 `_test` 库且无需要保留的回执时，才可按迁移状态执行 `0007` 的 downgrade 删除新回执表；若 DDL 部分成功而版本未推进，应由测试环境维护者审查后重建该独立空测试库并重跑迁移。生产环境需要单独备份、变更与恢复授权；本轮未在生产执行 DDL。

### 可重复的安全命令

在 `backend` 目录使用本工作树 `.venv/Scripts/python.exe`。先由测试环境维护者提供仅指向独立 `_test` 库的、Git 忽略目录内的 JSON 凭据文件，内容为 `database_url` 键（完整 URL 只写入本地文件，禁止输出或提交）。测试账号仅授权该库，数据库建库时显式设置 `CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_as_cs`。本轮文件位于隔离工作树 `.superpowers/runtime/mysql84/credentials.json`，不包含在提交或报告中；不要复用生产 URL。

```powershell
# 以下从隔离工作树 backend 目录执行；仅设置凭据路径，不展示文件内容。
$task6Credentials = (Resolve-Path -LiteralPath '../.superpowers/runtime/mysql84/credentials.json').Path
.\.venv\Scripts\python.exe scripts/mysql_acceptance.py preflight --credentials $task6Credentials --expected-database organization_agent_test
.\.venv\Scripts\python.exe scripts/mysql_acceptance.py migrate --credentials $task6Credentials --expected-database organization_agent_test
.\.venv\Scripts\python.exe scripts/mysql_acceptance.py capability --credentials $task6Credentials --expected-database organization_agent_test
.\.venv\Scripts\python.exe scripts/mysql_acceptance.py integration --credentials $task6Credentials --expected-database organization_agent_test
.\.venv\Scripts\python.exe scripts/mysql_acceptance.py backend --credentials $task6Credentials --expected-database organization_agent_test
# 单独验证无数据库时的明确 skip，不混入真实通过数。
.\.venv\Scripts\python.exe scripts/mysql_acceptance.py without-database
```

`scripts/mysql_acceptance.py` 先清除继承的所有 ORG_*，从文件读入测试 URL 并核对实际库名/结构/会话；只有迁移子进程同时设置 `ORG_DATABASE_URL`，pytest 子进程只保留 `ORG_TEST_DATABASE_URL`，避免真实飞书或应用配置干扰 HTTP 单测。它捕获子进程输出并脱敏 URL/密码，失败返回非 0。新建空 `_test` 库或当前 0006/0007 可验收；其他迁移状态先由维护者核查，不能跳版本。

独立双事务测试会提交用于并发证明的合成数据，按随机前缀清理事实/投影/审计/回执/任务并恢复 DatasetState；它要求库内原本没有部门、员工或任务，也不能与其他任务同时使用同一测试库。原有 savepoint 夹具仍用于其余事务用例。测试结束保留便携进程供后续 Evaluation 使用，最后由环境维护者关闭和删除凭据。

## MySQL 环境就绪后的执行方式

下列配置仅指向独立测试库。测试要求数据库名以 `_test` 结尾；每个用例的业务写入通过外层事务回滚，建表迁移需事先执行。

```powershell
$env:ORG_TEST_DATABASE_URL = 'mysql+pymysql://organization_test:local-integration-only@127.0.0.1:13306/organization_test?charset=utf8mb4'
$env:ORG_DATABASE_URL = $env:ORG_TEST_DATABASE_URL
Push-Location backend
.\.venv\Scripts\python.exe -m alembic upgrade head
Pop-Location
backend/.venv/Scripts/python.exe -m pytest backend/tests/integration -q
```
